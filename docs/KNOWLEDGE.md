# 知識放置規則與 5S 預算

> 回導航 [[README]] · 相關 [[LESSONS_LEARNED]]、[[tasks/00_INDEX]]
>
> **導航表不在這裡**——要找「哪個檔講什麼」請看 [[README]]。本檔只回答一個問題：
> **我手上這條知識該寫到哪裡去？**

## 知識該放哪層

| 知識的種類 | 放哪裡 | 形狀 |
|---|---|---|
| 任務進度與狀態 | [[tasks/00_INDEX]] | **唯一進度源**；任務檔只放執行細節與 hand-off |
| 架構決策 | [[01-architecture]] 的 ADR 段 | 一個決策一節；已定案的不改寫，用新 ADR 取代 |
| 踩過的坑 | [[LESSONS_LEARNED]] | **新的在上**；根因鏈 + 為何沒被攔下 + **預防 class** |
| 埠、位址、環境變數 | [[10-runtime-ssot]] | 別處一律指過來，不複寫 |
| 驗證指令與判準 | [[30-verification]] | 同上 |
| 部署與 plist 規則 | [[12-deployment]] | 同上 |
| 產出物 contract 流程 | `verification/` | 一個模型版本一個 rubric 檔 |
| 已完成的 campaign | `archive/` | 整包移入，**不得據以推斷現況** |
| 跨專案通用的做法 | 全域 skill 或全域 agent 規則 | 不放本 repo |
| 與某台機器或某個 agent 工具耦合的操作細節(兩機同步、shell 陷阱) | agent 的私有 memory | 不放本 repo:換人換機就不成立 |

判準：**與本專案耦合的 → 專案檔；換個專案仍成立的 → 全域。**

## 教訓的形狀（這條最常被寫壞）

每則教訓寫下可重複發生的**失效類別**、觸發條件與可執行的防線。
附上能區分正反例的檢查，讓下一個人能重現並阻止同類失效。
紀錄只保留判斷所需的證據。程序號、時間點、逐次重跑與完整輸出放回原工作收據。

能自動判定的防線交給最接近根因的既有測試或守衛。明列證據涵蓋的範圍。
同類已存在時，先指向既有條目，再補真正新增的失效條件。

## 專案記憶

架構、規格、進度與教訓以 Git 文件為準。客戶端的專案記憶索引只負責導航，
避免不同 checkout 或 agent 留下多份選版、部署狀態或舊目標。只在確有需要時，
另存仍有效的機器／客戶端操作知識，並記錄檢查日期。歷史工作指令不具現行授權。

## 產出、腳本與暫存

- 正式模型、STL 和單盤依模型清單保存於 `models/`。舊版及候選證據保留其來源、雜湊與索引。
- 共用、會維護的腳本放在對應的 `scripts/` 路徑。一次性實驗腳本與輸出同存原收據目錄。
- 清掃前先核對追蹤狀態、工作樹、證據引用與執行中的工作。只直接刪除可重建且與收據無關的快取；有追溯價值的產物歸檔。保持證據路徑、索引與雜湊一致。
- 通用 5S 掃描器用相對來源檔的規則解讀 wiki 連結。本 repo 的 docs 以 `docs/` 為根，連結與可達性以 `tests/unit/core/test_docs_dcc.py` 為準。

## 5S 預算

| 對象 | 預算 |
|---|---|
| Agent 指示檔（`AGENTS.md`／`CLAUDE.md`） | ≤ 200 行 |
| 專案自撰 skill（`SKILL.md`） | 約 150 行；細節外移到 references |
| 現行任務目錄 | 只留未驗收任務，含 `WAITING-ON-USER` |
| 供選擇性閱讀的檔案 | 超過 100 行要有目錄 |

**超標的唯一合法解是拆檔或歸檔，不是把句子壓短。** 壓縮語意會讓載重的指令
和裝飾性的句子一起模糊掉，比超標更糟。

## 節奏

- 每個 checkpoint 快速檢查任務索引、代理檔預算、專案記憶、被引用的產出與暫存。campaign 完成時跑完整一輪。
- 歸檔一律用**檔案搬移**，並在 commit 訊息裡點名搬了什麼——git history 是永久紀錄。
- 移出索引內容時，確認剩餘的任務入口仍可從導航抵達。用文件可達性及相對連結測試驗證搬移。
- **禁止靜默刪除**（無 commit 痕跡的移除），也**禁止改寫歷史**
  （`LESSONS_LEARNED` 與 `CHANGELOG` 的既有條目不動，要修就修現況）。
