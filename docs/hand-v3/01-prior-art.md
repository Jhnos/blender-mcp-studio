## repo 內部就有的東西(最大的一筆)

`src/core/domain/hinge_chain.py` 的 `HingePhalanxSpec` **已經是一個指節形狀的單軸連桿**:
本體 40 × 24 × 22 mm、有細長比檢查、最大關節角 ±50°、公舌／母叉單軸鉸鏈、
腱半徑 7 mm、軸承座 Ø8.1。它現在仍是活的,而且有測試(`tests/unit/core/test_hinge_chain.py`)。

**可復用的是連桿,不是串接規則。** 實測它的 `assembly_rotations_deg` 是 `(0, 90, 0, 90)`
——交替軸,對觸手對、對手指錯。V3 借連桿、換規則,詳見 [[hand-v3/03-finger]]。

只有它的**產生器**被歸檔在 `scripts/archive/model_hinge_chain.py`。
歸檔理由寫在 `scripts/archive/README.md`:**全樹零引用,不是幾何缺陷**。
同一份 README 也指定了復活的正確做法——先定義一個 `PresentationProfile`
(前綴／解析度／相機／燈光／地板),讓三支 render 變成三個 profile 常數,
**不是把 fork 搬回現行樹**。V3 照這條走。

**InMoov 的手指不是「單線 + 彈簧回位」** `[親驗]`。官網原文寫每指**兩條**線,
一條走上側、一條走下側;彈簧只負責手腕轉動時的線長補償
(「The springs are there only to give freedom to the length of the tendons when the
wrist rotates」)。所以使用者要的「三節單一線」與 InMoov 實作**是不同的機構**,
Track 2 不能照抄它的腱路徑。

## 外部:單腱三節怎麼依序閉合

`[轉引]` 文獻裡的機制有:各關節的**滑輪力矩臂比值**決定扭矩分配;
**扭簧勁度梯度**決定關節**接合順序**;分裂滑輪／浮動槓桿(whiffletree)差動把一個
致動器分給多個輸出;凸輪腱(變半徑)。理論基礎是 Birglen & Gosselin 2006。

**子代理搜遍 GitHub 找不到任何「三節單一腱 + 有記錄彈簧梯度」的開源 CAD。**
查無不等於不存在,但這是自己做的最強理由,也是 V3 唯一真正原創的機構部分。

實務上這是**兩個獨立旋鈕**:先調彈簧勁度比(決定順序),再調滑輪半徑(決定力量分配)。

## 授權後果

InMoov 與 Yale OpenHand 都是**非商業**授權,衍生物會繼承。目前 V3 是個人非商業專案,
所以可以用。但這代表兩件事必須做到:

1. `NOTICE` 檔記錄每一個外部來源與其授權,**這是一條機器可驗的規則**
   (見 [[hand-v3/02-requirements]] 的 VOC-3)。
2. **InMoov 的 STL 不進版控樹**。印來用,不提交。否則非商業條款會傳染給整包交付物,
   而且它進不了 spec 驅動的驗證管線——那條管線的每一道閘門都吃 spec,不吃匯入的網格。
