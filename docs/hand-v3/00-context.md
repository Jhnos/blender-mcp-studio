# 00 — V3 是什麼、不是什麼

> 回導航 [[hand-v3]] · 相關 [[hand-v3/01-prior-art]]、[[hand-v3/02-requirements]]

## 目標

一隻**單自由度線驅動的擬人手**,用來回答一個具體問題:

> 手指閉合之後,往雙層手套的夾層打氣,能不能顯著提高抓持力?能提高多少?

其餘所有設計決定都服務這個問題。任何不影響它的功能都不做。

## 與 V1／V2 的關係:平行,不是繼承

| | V1／V2(章魚手) | V3(擬人手) |
|---|---|---|
| 拓樸 | 五臂放射對稱 | 四指一排 + 對生拇指 |
| 每肢關節 | 4 個雙軸萬向 | 3 個單軸 |
| 腱 | 20 條 | 每指 1 條 |
| 閉合方式 | 每個關節獨立 | 一條腱連動三節(欠致動) |
| 軟層 | 無 | 雙層手套 + 針筒充氣 |

程式上這代表 **V3 用組合,不用繼承**。`OctopusHandV2Spec` 的每一條不變式都預設
放射對稱與雙軸關節;V3 不滿足那些前提,繼承會違反 LSP(子型別必須能替換父型別)。
V3 **組合** `HingePhalanxSpec`,那是 repo 裡本來就有的單軸指節鏈。

## 兩條軌並行

- **Track 1 — 實體試驗台**:直接印 InMoov 的手,套兩層手套,量數字。
  不寫任何幾何程式。它回答上面那個問題。詳見 [[hand-v3/08-inmoov]]。
- **Track 2 — 生成式幾何**:V3 自己的 spec 驅動幾何,吃 Track 1 量到的數字。

分軌的理由是:最不確定的事是「充氣有沒有用」,而回答它需要**一隻手**,
不需要**我們的手**。

## 明確不做

- 不動 `models/octopus-hand-v1/`、`models/octopus-hand-v2/`、`models/biaxial-hinge-v6/`
  的任何位元組,也不動 V1 的產生器與契約。
- **不把 InMoov 的 STL 提交進版控樹**。印來用、署名引用,不進 repo。理由見
  [[hand-v3/08-inmoov]] 的授權段。
- 不做氣密工程、不做矽膠模具、**不設計外層手套**。外層是雛型出來之後的採購決定。
- 不宣稱任何抓持力、摩擦係數、壽命或列印成功,**直到台架量到數字為止**。
- 不碰 web／API／MCP 任何一層。

## 尚未決定的事

- 拇指對生軸的角度與掌盤的實際尺寸,等 Track 1 的人因回饋。
- 伺服型號與腱力預算,見 [[hand-v3/05-actuation]] 的待填欄位。
