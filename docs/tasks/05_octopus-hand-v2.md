# 五臂章魚手 V2 — 角點對齊手臂、加強莖、瞄準式抓取墊

**Status:** AWAITING-ACCEPTANCE

## Goal and context

V1 的五邊形掌盤有個沒人決定過的缺陷:角點落在離手臂 18° 的地方,那只是 Blender 五邊形
圓柱起始相位的副產物。後果是上下顛倒的——不承載的角上材料最厚,承載承接座的邊上材料最薄。

使用者 2026-09-06 提出六點修正:①角點對齊手臂並長出加強莖 ②抓取墊朝向自由度方向並
漸進混入圓盤 ③每臂開走電線的孔 ④消除直角改斜角 ⑤床身改為 Bambu Lab P2S 的 256 mm
⑥外型更友善。

**「不覆蓋」是硬需求**:V1 已經是 checksum 控管的交付物,`models/octopus-hand-v1/`、
`scripts/model_octopus_hand.py`、`scripts/octopus_palm_geometry.py`、
`scripts/octopus_grip_geometry.py` 與 V1 的兩份契約一個位元組都沒動。V6 同樣未動。

## Current specification

- 掌盤:正五邊形**轉到角點落在每個手臂航向上**,五角截平 3.0 mm,上下緣 45° / 1.5 mm 倒角。
  內切圓 53.495、外接圓 66.123、角平面 63.123、包絡半徑 63.258 mm。匯出實測
  116.618 × 122.619 × 18.800 mm。
- **內切圓推導改變**:邊只需在偏離航向 36° 處讓開承接座,所以站位半徑乘上 `cos 36°`。
  V1 是 `41.5 + 17.92 + 2.0 = 61.42`,V2 是 `41.5·cos36° + 17.92 + 2.0 = 53.495`。
- 承接座後方材料:V1 恰好一道壁 2.00 mm,V2 為 **3.703 mm**(已扣掉截角)。
- 加強莖:每臂一道,半徑 48.0 → 60.0 mm,高 8.0 → 1.2 mm,坡度 29.5°(朝上,免支撐),
  半寬 6.0 mm。最窄處距離基座關節掃掠地板 **2.87 mm**。
- 抓取墊:四片移到**正交方位 0/90/180/270**。每節扭轉 0° 或 90°,朝掌心的局部方位就是
  180° 或 90°,兩者皆為正交方位,所以**每一節都有一片墊正對抓取方向**,且集合在 90°
  扭轉下映射到自己,仍只需一個 master。上緣加 0.6 mm 倒角,剖面五點。
- 電線孔:每臂 Ø6.0 mm,位於該臂航向、掌心半徑 30.0 mm(內縮到承接座根腳旁邊),
  與中央 Ø10 通道並存。
- 指尖端蓋外擴量 3.0 → **4.0 mm**(斜角 38.7°),見下方 open failure 的根因。
- 整機:119.442 × 124.934 × 118.000 mm,131 824 三角面,76 個獨立殼體。
  **床身佔位 129.342 mm 由手臂決定,不再由掌盤決定**(V1 是 151.840,由掌盤決定)。
- 這些是配合用的原型尺寸,不是認證過的軸承、保持件或承載件。

## Hand-off

### Verified facts

- **兩份真機契約全綠、零 SKIP**:`octopus_hand_v2.json`(16 項)與
  `octopus_hand_v2_tips.json`(9 項)。含 −34°…+34° 十五點掃掠零重疊、六組碰撞零重疊、
  五指尖互比零重疊、掌盤中央通道 `center_ray_hit=false`、就緒 `status=review` **未截斷**、
  無禁止的結構錯誤碼。
- **「每節都有一片墊正對抓取方向」是量到的,不是推的**:沿朝掌心方向射線,兩隻手臂共十節、
  自身扭轉 0/90/144/234 各異,打到的都是半徑 **21.000 mm** 的墊面(裸圓盤是 18.0)。
- **正交方位比對角方位更寬**:在真實 V1 網格上做全行程掃掠,墊對墊間隙對角是 **0.204 mm**、
  正交是 **0.553 mm**。V1 註解說「耳片佔住正交方位」對輪緣而言是錯的——耳片與根腳最遠只到
  半徑 16.70 mm,墊活在 17.2–23.17 mm。
- **加強莖的高度是掃掠地板給的,不是猜的**:基座關節掃掠底面在半徑 60 mm 附近有個咽喉,
  掌面上只剩 4.07 mm;莖的斜坡順著它收下來,最窄處仍有 2.87 mm。
- **視覺 rubric 判過四輪、四位獨立判定者、每一項零 FAIL**。渲染從 11 張補到 16 張,
  每一輪的 UNCLEAR 都在說「圖不夠」,沒有一輪說「模型不對」。第一輪還抓出一張全黑的
  底面圖——地板平面擋住了相機,那是渲染的 bug,已修。
- **五個電線孔逐一驗過貫通**:`open_bores` 的 `bore_ray_hits = [False]×5`。為此擴充了
  oracle 的 `bore_probe_points_mm`(選填;缺席代表不宣稱,回報數量不足即 fail-closed),
  連同 9 項新測試——含「回報兩個就當五個都通」那種部分答案必須翻紅的案例。
- 三個主件在 Blender 內量測全部水密:0 邊界邊、0 非流形。
- 包已發布:`models/octopus-hand-v2/` 六檔,manifest 由不使用 Blender 的獨立解析器讀回,
  跨機器傳輸後校驗碼全數吻合。三角面數在 macOS 與 Windows 兩台上完全相同。
- Python 側閘門在 Mac 上全綠:ruff、ruff format、mypy strict 全樹、container-narrowing、
  **651 項 unit + e2e**。
- V1 未受影響:V1 的 32 項 spec 測試、兩份契約與包校驗測試維持全綠。

### Open failures and limitations

- **沒有任何實體列印**,脫模、支撐策略、配合、抓取力、驅動線張力與疲勞全部未測。
- 臂朝上時銷軸變水平,Ø4.5 銷孔成橋接、captive PIN 頂部懸空——與 V6 建議方向相反,
  只有實體列印能回答。這是第一份實體件要驗的事(V1 遺留,V2 未改變)。
- 視覺 rubric 的 **C、I、J 三項在四輪之間擺盪**(第三輪修好 C 卻弄丟 I,第四輪反之),
  代表它們卡在著色渲染圖的解析極限,不是模型不穩。三項都改由量測背書,不再加圖;
  細節見 [octopus-hand-v2.md](../verification/octopus-hand-v2.md) 的 rubric 段。
- 就緒檢查回報 430 個薄壁、3972 個懸空取樣面警告,供切片與實體審查,不認證強度或支撐策略。
- 抓取墊給的是接觸**面積**;接觸力、摩擦係數與任何特定形狀物體抓不抓得住,完全沒有量。
  總面積 312 mm² 比 V1 的 355 少 12%,換來的是 79% 的面積朝向抓取方向(V1 是 0%)。
- 加強莖與掌盤的碰撞只驗到「莖在掃掠地板之下」這條保守界線(以手臂中心線為最壞情況),
  不是連續證明;實際幾何在 Blender 掃掠裡另外驗過,但掃掠比的是節體對節體,不是節體對莖。
- 掌盤 ↔ 第一節的間隙不在任何相鄰比對群組內(V1 遺留)。
- 臂間相鄰比對涵蓋 1↔2…4↔5,**5↔1 沒有直接比對**,靠正五邊形對稱性覆蓋(V1 遺留)。

### V2.1 — 端蓋改成八邊並轉半個面(2026-09-08)

使用者指出:「這樣指尖節也要做成8邊形 不然有一個自由度會是斜角」。量測證實這是對的——
在建好的 `HH_OCT2_MASTER_TIP` 端蓋中段高度沿四個抓取方向射線量:

| 航向 | 半徑 mm | 表面離正交 | 手指碰到的是 |
|---|---|---|---|
| 0 | 16.000 | 30.0° | 角 |
| 90 | 13.856 | 0.0° | 面 |
| 180 | 16.000 | 30.0° | 角 |
| 270 | 13.856 | 0.0° | 面 |

**但單純把 6 改成 8 會更糟一半而已**:面心要同時落在四個正交方位,facet 數必須是 4 的倍數
**而且**整圈要轉半個面。8 不轉是 22.5° 偏差,仍然是角。8 轉 22.5° 才是 0.0°;12 也行,
代價是接觸面從 16.073 mm 窄到 10.870 mm。改完重建,四個方向都量到 0.0°,V2 每個物件仍是
零非流形邊,端蓋多 24 個三角面、整機多 120 個,沒有任何尺寸改變。

相位是 grip spec 上的一個 property,不是端蓋建構器裡的常數,V1 回答 0.0,所以 V1 的端蓋
仍由它一直以來的座標建出來。

**這裡也補了一道量成品而非量規格的閘**。第一次修的時候只把 facet 數改成 8,`create_cap`
還在用相位 0 建,而所有 domain 測試全綠——關於規格的算術看不到成品。閘的第一版掃多邊形法向
**沒有鑑別力**:中央通道與纜線孔都用 24 段鑽,孔壁能對任何航向提供半度內的法向,把一個
故意轉歪的端蓋放行了。改成射線後只看得到手指真正會碰到的那個面,並用「把成品網格轉半個面」
證明它會紅。

### 過程中修掉的兩個真缺陷

1. **`export_stl_mm` 漏還原 `hide_render`(既有缺陷,V1 也中)**。生成器匯出前會把 master
   藏起來,而新版 Blender 的 STL 匯出器尊重 `hide_render`,於是 `arm_body`、`arm_tip`、
   `test_coupon` 三個檔都寫成 84 bytes 的零三角面 STL。拿 V1 自己的生成器在 Blender 5.2.1
   上重跑,重現同樣三個空檔;出貨的 V1 檔案是在不會這樣的 Blender 上做的。已在瓶頸點修正,
   並讓「寫出零三角面」直接 raise。
2. **端蓋外擴恰好 45° 會擦過圓盤外緣**。`tip_cap_flare_mm = 3.0` 使端蓋半徑在切頂平面上
   正好等於圓盤半徑 18.000,表面擦過被切開的外緣邊而非穿過,下一個 boolean 就在端蓋facet
   角落開出 12 條邊界邊,再被腱孔鑽成 204 條非流形邊。V1 逃過純屬運氣(對角墊剛好埋掉六個
   角中的四個)。改為 4.0(38.7°),並加了一條機器擋得住的不變式。
