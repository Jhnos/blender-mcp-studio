# v3 — 框架會怎麼壞

> 回導航 [[hand-framework/v0-INDEX]] · 相關 [[hand-framework/v2-hypotheses]]、[[hand-framework/v4-scenarios]]、[[LESSONS_LEARNED]]

先列「它會怎麼壞」,每個失效模式各配一個夾具與一條斷言。
**本專案已經踩過的優先**——它們不是假想,是 [[LESSONS_LEARNED]] 2026-09-08 那一段的紀錄。

## 已經發生過、框架要結構性擋掉的

| ID | 失效模式 | 這輪的實例 | 誰會抓到 |
|---|---|---|---|
| FF-1 | **散文描述產物,而閘門只驗產物** | README 講四節的手;三份文件三個年份的同一個數字 | 圖表守衛:表格數字由規格算 |
| FF-2 | **追溯 ref 是死連結,格式檢查器永遠說綠** | 22 個 ref 21 個不存在 | ref 解析守衛 + `TODO_` 前綴 |
| FF-3 | **宣告的母數前綴不存在** | 五份文件寫 `HH_V3_`,產生器用 `HJ_` | 母數守衛從產生器讀前綴 |
| FF-4 | **兩個獨立算式各自產生一個位置** | 進氣口鑽穿袖口夾帶(−50.4 vs −50.0) | 位置關係在規格裡有名字 + 不變式 |
| FF-5 | **修 A 時把零件扯成兩塊,逐面檢查全盲** | 每個指節兩個殼,契約 19/19 綠 | `expected_shells_per_object` |
| FF-6 | **相鄰配對頂替全配對** | 拇指對四指沒人量;佈局兩列重疊 | `disjoint_groups` |
| FF-7 | **改了參數,讀它的程式沒跟上** | 走線孔寫死 6.6 撞進 15 mm 本體的壁 | 字面值帳本 + ES-5 靜態掃描 |

## 框架新引入的失效模式

| ID | 失效模式 | 誰會抓到 |
|---|---|---|
| FF-8 | **契約由規劃生成,但簽入檔沒重生**——契約與規劃靜默分歧 | T2:生成器輸出 == 簽入 JSON |
| FF-9 | **新模組沒進 `reload_modules`**,常駐 Blender 跑舊碼還綠 | ES-6 靜態掃描 import 圖 |
| FF-10 | **`ExpectedCounts` 與契約計數對不上**(站台數、佈局件數) | 契約由同一個 `ExpectedCounts` 生成;差分 |
| FF-11 | **執行層偷偷算術**——把一個字面值搬回 bpy 模組 | ES-5:浮點/字串字面值白名單 |
| FF-12 | **兩個實例共用命名空間**,建第二個清掉第一個 | `NamingPolicy` 每實例一前綴;一致性套件斷言前綴互異 |
| FF-13 | **掌盤絕對常數對淺連桿靜默錯**(拇指根凸出 7 mm) | I1/I2 不變式;一致性套件 `strict=True` |
| FF-14 | **把 STL 雜湊當回歸判準**,假回歸或假通過 | 差分只比面數與尺寸;文件明寫不可位元組重現 |
| FF-15 | **等臂守衛被繞過**——梯度實例靜默變成等臂 | `expected_shared_mesh_count` 對梯度實例宣告 N |
| FF-16 | **任務狀態說謊**——ACTIVE 掛著沒人在推的任務 | `WAITING-ON-USER` 狀態;checkpoint C1 |
| FF-17 | **新閘門第一次就綠而它在量錯的東西** | 每個新閘門附 should-fire 夾具(v1 驗收準則 5) |
| FF-18 | **閘門用一個實例的運氣校準**——V3 面數精確重現,精簡實例每零件 ±2 面(exact solver 輸出順序不定 + cleanup 門檻) | 差分的碎片預算由規劃推導(每布林零件 ±2),預設 0;探針記錄在 v8 |

每一列在 [[hand-framework/v4-scenarios]] 至少有一個場景,在 [[hand-framework/v7-matrix]] 至少有一列。
